# CLAUDE.md

Transport-mode classifier from phone sensors (internship project for WAIIS Mobility).
Input: accelerometer + gyroscope at 25 Hz (6 channels, m/s² and rad/s, arbitrary orientation).
Output: transport mode per window. The model will eventually run on a phone, so every model
is judged on accuracy **and** cost (size, latency, compute). Python only, batch over files, no app.

## Commands

- Install / sync: `uv sync`
- Tests: `uv run pytest` — must pass before any task is considered done
- Lint / format: `uv run ruff check . && uv run ruff format .`
- Each results table has exactly one script in `scripts/` that regenerates it from scratch

## Layout

- `src/tmd/io/` — one reader per dataset, all returning the common frame (below)
- `src/tmd/resample.py` — resampling to 25 Hz
- `src/tmd/windows.py`, `features.py` — windowing and hand-crafted features
- `src/tmd/evaluate.py` — the single evaluation function every model goes through
- `src/tmd/config.py` — paths (from env var `TMD_DATA`), `SEED`, constants
- `tests/` — pytest; `scripts/` — one entry point per results table; `results/` — exported tables

## Common data frame

Columns: `user_id`, `session_id`, `t` (seconds, float), `acc_x`, `acc_y`, `acc_z` (m/s²),
`gyr_x`, `gyr_y`, `gyr_z` (rad/s), `position`, `label`.
Labels are kept at the finest available granularity (SHL's 8: Still, Walk, Run, Bike, Car,
Bus, Train, Subway) and collapsed to the evaluated rung only at evaluation time:

- Rung 1: `still`, `foot`, `vehicle`
- Rung 2: `still`, `foot`, `bike`, `road_vehicle`, `rail_vehicle` (Run → `foot`)
- Rung 3: individual modes

Never merge Run into Walk in stored data.

## Non-negotiable rules

1. **25 Hz everywhere.** Every dataset is resampled to 25 Hz before any feature or model sees
   it. Resampling uses an anti-aliasing low-pass before decimation (e.g.
   `scipy.signal.resample_poly`), never index skipping. Short gaps are interpolated, long gaps
   cut the series into segments. Native-rate results exist only as a separate comparison table.
2. **Split by user, never by window.** Leave-one-user-out (or grouped by `user_id`). Random
   window splits are forbidden.
3. **No leakage.** Normalisation/scaling statistics are fit on the training fold only.
   Hyperparameters are never chosen on the final test set. The final test set is not touched
   until the close of the project.
4. **One evaluation path.** Every model goes through `evaluate.py`, which reports macro-F1
   (main metric), per-class recall, confusion matrix, breakdown by phone position and dataset,
   and the cost KPIs. A model without its cost is not a result.
5. **Reproducibility.** Seeds come from `config.SEED`. Every experiment is logged to MLflow
   with parameters, seed, commit and metrics. Runs from a dirty git tree are refused or tagged
   `dirty=true`. A number that cannot be regenerated by a script does not go in the report.
6. **No data in git.** Data lives under `$TMD_DATA`, outside the repository. Never commit
   data files, model weights over a few MB, or the MLflow store.
7. **Licences.** Nothing under an academic-only licence (e.g. Oxford `ssl-wearables`) in the
   recommended model. Any new dataset or pretrained model gets an entry in `LICENSES.md`.
8. **Sensor model stays sensor-only.** GPS, map, GTFS and OSM information is a separate,
   clearly marked stage for validation and exploration. Never add it to the sensor model's
   features.

## Phone budget (for cost measurements)

| KPI | Target | Hard ceiling |
|---|---|---|
| ONNX model size | ≤ 500 KB | 2 MB |
| Latency per 5 s window (features + inference, laptop, 1 thread) | ≤ 2 ms | 10 ms |
| Peak inference memory | ≤ 20 MB | 50 MB |

Latency protocol: same machine, single thread, warm-up, 1,000 windows, report median and p95.
Measure feature cost separately from model cost. Models must export to ONNX.

## Conventions

- Python 3.11, type hints on public functions, NumPy-style docstrings on non-trivial functions.
- Default windows: 5 s, stride 2.5 s. Window label = majority label; mixed windows are excluded
  from training but kept in evaluation.
- Orientation-invariant channels: acceleration magnitude, vertical component (gravity via
  ~0.3 Hz low-pass), horizontal magnitude, rotation magnitude.
- Prefer the simple baseline (features + LightGBM) before deep models; new models are compared
  against it.
- When writing new functionality, write the tests first (synthetic signals where possible),
  then the implementation.
- Don't add dependencies without saying why; use `uv add`.
