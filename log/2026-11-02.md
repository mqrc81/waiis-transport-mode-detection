## Experiment 09: frozen benchmark waiis_bench_v2

*(Details in `experiments/09_frozen-benchmark_es-shl-nor-collecty/README.md` and `decision_register.md`.)*

- v1 + NOR-TMD (Android) + Collecty; 9 fine classes (tram added). Primary score: six-class macro-F1 (still, foot,
  bike, car, bus, rail) on ExtraSensory dev, pooled out of fold; guard: NOR-TMD dev (bus, car, rail).
- Reserved set v3: v2's ExtraSensory and SHL users + 14 NOR-TMD installations (8 whole device models, as a person
  guard), scored on bus, subway, train, tram, car.

| Dev windows (official) | v1 | v2 |
|---|---|---|
| rail (train + subway + tram) | 5,931 | 11,127 |
| bus | 4,376 | 9,985 |

- v1's references in the six-class score: 05 test 0.642 (dev 0.575), 06 test 0.686 (dev 0.642).
- Rules added: real rate ≥ 24 Hz; per-user cap per class (top user ≤ 25%); iOS to the Android axis convention;
  conflicting labels (NOR-TMD outside / inside, Collecty walk) as unlabelled minutes.
- **Run labels:** 07's dev / test run gap came from one ExtraSensory dev user whose "run" moves like walking. Users
  whose run moves less than a typical walk have no run labels (7 users; dev run 463 → 155, test 81 → 74).
- Source is identifiable within class from 05's features (AUC 0.82–0.96, tram 0.52): the shortcut checks belong in
  the first model on v2.
- v1 unchanged: rebuilt hash-identical and 06's dev out-of-fold probabilities bit-identical after every change;
  04–08 now pin `waiis_bench_v1`. Default still v1.
