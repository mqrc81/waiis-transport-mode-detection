## Experiment 04: frozen benchmark `waiis_bench_v1`

*(Details in `experiments/04_frozen-benchmark_es-shl/README.md`.)*

- Renamed to **`waiis_bench_v1`**; rebuilt in a clean worktree from commit `e51ea79`, every file's sha256
  reproduced. Read with `tmd.bench`; `tmd.bench.verify()` checks it against the committed manifest.
- ExtraSensory: 145,380 official examples (59 users), 5 dev folds by user + 12 test users. SHL User 1: 23,076
  (training only). SHL Users 2–3: 2,365 (rail check).
- Thin classes: ES train from 5 users (test: 2 Android users, 52 examples), run from 22.
- Location coverage: iPhone 93%, Android 67%. GPS is one fix per minute, sparser than WAIIS (~10 s when moving).
- New rule: ES cross-validation metrics come from pooled out-of-fold predictions (folds differ in size and
  classes), per-fold scores only as spread.

## Experiment 05: accelerometer-only LightGBM + HMM (plan, dev ablation)

*(Details in `experiments/05_acc-baseline_waiis-bench/README.md`; runs in MLflow `05_acc-baseline_waiis-bench`.)*

- 580 features (features v1 without gyro on the 15 s window + stats over 5 s sub-windows), LightGBM on ES dev +
  SHL User 1, HMM forward-backward per session.
- Dev ablation (ES family F1, paired CI):
  - HMM: +0.120 [+0.096, +0.144], by far the largest gain;
  - SHL User 1 in training: +0.031;
  - sub-window statistics: +0.013;
  - gravity features n.s.; 10 Hz low-pass slightly worse;
  - context over neighbouring minutes identifies the dataset and adds nothing after the HMM: not adopted.
- Trade-off: the HMM cuts ES rail recall on dev (0.24 → 0.08) but removes almost all false rail elsewhere.
- User bootstrap fixed to redraw resamples that lack a class.
