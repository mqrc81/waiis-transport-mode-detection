## Experiment 06: accelerometer + GPS fusion

*(Details in `experiments/06_gps-acc-baseline_waiis-bench/README.md`; runs in MLflow `06_gps-acc-baseline_waiis-bench`.)*

- GPS model: LightGBM on 13 GPS features from one fix per minute (gps-v2: derived speeds, acceleration, stops,
  heading change), trained with SHL User 1. Fused with 05's acc model by product of probabilities (acc alone
  without GPS), then the HMM.

| `waiis_bench_v1` | 8-class (06 / 05) | family (06 / 05) |
|---|---|---|
| ES test (mean of 3 seeds) | **0.707** / 0.666 | **0.747** / 0.698 |
| — iPhone / Android | 0.764 / 0.682 | 0.847 / 0.708 |
| ES dev, pooled out-of-fold | 0.613 / 0.551 | 0.681 / 0.615 |
| SHL Users 2–3 | 0.847 / 0.795 | 0.944 / 0.932 |

- Product fusion +0.061 on dev; stacking adds nothing, early fusion is worse. SHL User 1 helps the GPS model too.
- **Platform check failed but overridden** (recorded deviation): GPS features identify iPhone vs Android within a
  class (walk AUC 0.73). A GPS model trained without one platform gives the same gain on it, so the gain doesn't
  rely on that. Draft DECISIONS entry: judge GPS platform effects by this transfer test, not by the AUC.
- Weak: no 8-class gain on iPhone test users, walk recall falls (0.715 → 0.650), bus still low (0.25).
- Cost: 1.4 + 3.8 MB, ~12 ms per single window.
- **06 is the new reference** (`STATUS.md`). Next experiment not decided: InceptionTime + GPS or LIMU-BERT from scratch.
